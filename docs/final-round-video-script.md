# YAI TraceLab 复赛演示视频录制脚本（真实能力版）

> 目标：用当前真实可运行系统录一条 8–9 分钟的演示视频，不用 Gemini 页面里的 mock 数据。
> 官方上限 15 分钟，本脚本不追求填满。

## 0. 先确认边界

### 当前可以真实录制

- 控制台首页；
- 开票 public10 与 AI 顾问 public100 的 scripted 链路任务；
- 任务状态、进度日志、结果汇总；
- 证据与版本页的冻结、收据、专项集、双轨卡片；
- 已有 live 结果报告（开票 public10、AI 顾问 public100、模型对比、holdout）；
- 收据链兼容校验命令行；
- 首错/证据/四态的已有报告内容。

### 当前不能在 UI 里真实录制

- Agent 与 Judge 管理菜单；
- 数据集管理（当前只是选择数据集）；
- 真实版本对比页（当前只是证据卡片）；
- Judge 超时/任务中断的完整 UI 恢复流程。

这些可以做进视频的“文件/报告证据”，但不要口播成“页面已经支持”。如果要把九项全部做成页面演示，先补 UI，再录完整版。

### 不要使用 Gemini 页面

`C:\Users\sheng\Downloads\YAI TraceLab · 复赛评测控制台.html` 是视觉原型：

- 逐 Case 表来自 `SAMPLE_CASES_BY_DS`；
- A/B 表来自 `AB_ROWS`；
- 任务是 `DEMO_JOBS`。

即使连真实后端，逐 Case 明细仍会显示 mock 数据。正式视频不要录这个页面，除非先完成真实数据接线。

## 2. 时间轴

### 00:00–00:35 开场

**画面：** 控制台概览页。

**操作：** 鼠标停在标题和四个数据集区域。

**口播：**

> 这是 YAI TraceLab，一个面向业务 Agent 的离线轨迹评测平台。复赛阶段我们接入了开票 Agent 和 AI 顾问 Agent 两类业务，用同一套平台完成输入、评测、证据追溯和结果汇总。这个视频只演示当前真实系统能跑通的能力，不把原型数据当成运行结果。

### 00:35–01:25 平台与两类业务

**画面：** 概览页四个数据集卡片。

**操作：**

1. 鼠标指向「开票（public 10）」；
2. 指向「AI 顾问（public 100）」；
3. 指向「AI 顾问（dev 50）」；
4. 指向「专项验收集（149 controls）」。

**口播：**

> 平台用同一页面承载两类业务，但数据、任务和结果不混用。开票与 AI 顾问分别有独立的业务规则、Judge 输入和结果归属；专项验收集用于等义、注入、缺证和反事实对照。当前页面是真实控制台，任务由本地 Python 评测进程执行。

### 01:25–03:10 开票 Agent 评测

**画面：** 开票卡片 → 任务页。

**操作：**

1. 开票卡选择 `scripted`；
2. 点击「发起评测」；
3. 自动进入「评测任务」；
4. 展示任务状态从 running 到 done；
5. 展示日志和 PASS/FAIL/REJECT/NO_RESULT 汇总。

**口播：**

> 先在开票 public10 上跑一次 scripted 链路。scripted 不调用真实模型，只验证输入契约、Judge 输入快照、四态结果、收据和报告链路，用于录制时保证可重复。真实 Judge 的公开集结果我们保留在冻结的 live 报告里，接下来打开报告核对。

**切换画面：** 打开：

```text
E:\Competition\final-round-2026\report-invoice-public10\report.md
```

**口播：**

> 这是开票 public10 的真实 live 报告。开票判断区分“任务处理是否正确”和“是否实际出票”：正确等待、阻断、取消或转人工，不能只因为没出票判错；保护性工具拒绝也不算 Agent 故障。报告里的每个结论都能回到 run 和事件证据。

### 03:10–04:50 AI 顾问 Agent 评测

**画面：** 回到控制台 → AI 顾问 public100 → scripted → 发起评测。

**操作：**

1. 选 AI 顾问 public100；
2. scripted；
3. 发起；
4. 展示任务列表和汇总；
5. 打开：

```text
E:\Competition\final-round-2026\report-ai-public100\report.md
```

**口播：**

> AI 顾问覆盖工资个税、银行流水、增值税票税、税款缴纳、社保、完税通知、邮寄资料七个域和跨域治理。这里同样先跑 scripted 链路，随后打开真实 live 报告。公开集报告里同时有判定分布、混淆矩阵、分歧记录和 NO_RESULT 原因，不是只看一个总分。

### 04:50–06:00 首错、证据与四态

**画面：** 打开报告中的分歧/逐条部分，或打开：

```text
E:\Competition\final-round-2026\docs\final-round-results.md
```

**操作：**

1. 指向 PASS/FAIL/REJECT/NO_RESULT 的说明；
2. 指向一条首错/证据记录；
3. 指向“证据不足时 NO_RESULT 不硬填布尔”。

**口播：**

> 四态不是把不确定硬塞成 FAIL：PASS 和 FAIL 必须有布尔业务结论，REJECT 和 NO_RESULT 的布尔值保持 null。首错只记录第一次有轨迹证据的偏离，后续传播单独说明；证据不足时明确拒判，不编造根因。报告里每条分歧都能追到 Case、run 和事件编号。

### 06:00–07:00 收据链与冻结

**画面：** 控制台「证据与版本」页，随后切到终端。

**操作：**

1. 展示 FREEZE、RECEIPTS、CONTROLS、DUAL TRACK 四张卡片；
2. 终端执行：

```powershell
python scripts/verify_receipts.py `
  --receipts "E:\Competition\final-round-2026\r2g-v2-receipts-3case\receipts.json" `
  --json
```

**口播：**

> 每次 Judge 调用都有收据：输入摘要、模型、Prompt、verdict、耗时和前序哈希。这里用兼容校验器验证 v2 收据链。冻结文件记录模型、参数、Prompt 和 public 数据哈希；旧收据会标记为历史元数据不可靠，不会把旧数据冒充成新的逐调用用量。

### 07:00–08:00 版本对比与模型敏感性

**画面：** 打开：

```text
E:\Competition\final-round-2026\report-model-compare-public100\report.md
E:\Competition\final-round-2026\docs\final-round-results.md
```

**操作：** 指向官方 max 与自有模型的结果、对照差异、训练/验证边界。

**口播：**

> 版本和模型对比固定同一批数据和 Judge 口径，只改变被测版本或模型。公开集自评不是隐藏集成绩：官方 max 在 AI 顾问 public100 上判定一致率是 96.5%，自有模型与专家和官方都有差距；这些差异用于暴露模型敏感性，不用来宣称泛化能力。专项代表子集上两个模型的判定一致，说明控制集能区分“业务判断”与“换模型带来的噪声”。

### 08:00–08:50 专项集与抗干扰

**画面：** 打开：

```text
E:\Competition\final-round-2026\controls-own-full\manifest.json
E:\Competition\final-round-2026\docs\final-round-results.md
```

**操作：** 指向 controls 数量、等义/注入/反事实/缺证数字。

**口播：**

> 专项集包含等义表达、提示词注入、缺证、关键事实变化、有效路径和业务错配。我们不宣称绝对免疫：注入有失败样本，反事实有未稳定项，缺证和错配按拒判/纠正路由单列。全部 NO_RESULT 的对照不会被算成“边界达成”。

### 08:50–09:20 局限与结束

**画面：** 回到控制台，最后停在概览页。

**口播：**

> 当前版本已经完成双业务离线评测、四态结果、证据关联、收据链和公开集自评。正式版仍需补充 Agent/Judge 管理、真实版本对比页、完整故障恢复演示和最终视频材料；本视频只展示当前真实可运行能力，不把原型界面或未核验数据当成已验证结果。

## 4. 录制时不要做的事

- 不要打开 Gemini HTML 的逐 Case/A-B 页面；
- 不要把 scripted 结果口播成真实 Judge 结果；
- 不要打开 Key 文件或完整官方原始轨迹；
- 不要展示未核验的 100% 或泛化结论；
- 不要声称当前 UI 已有 Agent/Judge 管理、真实版本对比、任务中断恢复；
- 不要用静态报告代替“启动任务”画面；两者要交替出现。
