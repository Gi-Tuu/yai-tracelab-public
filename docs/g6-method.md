# G6-A：Metamorphic Evaluation（评测器自身的稳定性检验）

> 目标：不增加规则数量，而是回答一个更难的问题——**评测器的判断是否只随业务事实变化而变化**。
> 全部实验离线运行、样本 100% 自造（`tracelab/samples.py`；`tests/builders.py` 只是再导出），不读也不改官方资料包；
> 结论只对本批自造样本成立，**不是真实业务泛化准确率**。

## 1. 两类实验

| 类别 | 改什么 | 期望 |
|---|---|---|
| **语义保持（invariance）** | 只改与业务事实无关的东西：事件编号、无关元数据、描述文本、金额的等价字符串写法、事件数组顺序、映射键顺序 | 判定、业务结果、规则集合、质量分、首因（按 ID 映射后）、证据引用**全都不变** |
| **业务语义变化（sensitivity）** | 只改**一个**业务事实：确认、口径、税额、商品、条目、意图、重复风险、参数漂移、提交状态、回调、购方编造/消歧 | 触发**对应规则**、判定符预期、**不牵连**其它规则、首因落在业务发生的那一步 |

关键设计约束：预期值是**按业务含义预先写死**的（见 `tracelab/experiments.py` 的 `VariantSpec`），
不是跑完评测器再回填——否则实验会退化成"用输出验证输出"。

## 2. 实现位置

- `tracelab/metamorphic.py`：6 类纯变换（`Case → Case`，附变更记录与事件 ID 映射）+ 比较器 + 统计。
  变换**不调用评测器**，只重建数据；判定仍完全交给 `attribution.assess_run`。
- `tracelab/experiments.py`：18 个声明式变体（每个写明改了哪些字段、应触发哪条规则、判定、不得牵连的规则、首因位置）
  + 指标汇总 + 简短 markdown 渲染。

## 3. 实测结果（固定种子 `20261104`）

### 3.1 语义保持

| 指标 | 分子 / 分母 | 比例 |
|---|---|---|
| Invariance Consistency | 42 / 42 | **100.0%** |
| 不一致样本对 | 0 | — |
| 预期之外 UNKNOWN | 0 / 42 | — |
| 预期内 UNKNOWN（REFUSAL 语料 × 6 类变换） | 6 / 42 | — |

样本为 7 个自造 Case（含 1 个**应被拒判**的样本）× 6 类变换。按变换拆分（每类 7 组，全部一致）：
`rename_event_ids`、`add_unrelated_metadata`、`edit_descriptive_fields`、
`money_equivalent_representation`、`reorder_event_array`、`reorder_mapping_keys`。

其中"改名"是唯一需要**映射后比较**的变换：比较器把修复前的首因事件 ID 与证据 ID 经 `id_map` 换算后再比，
因此能区分"编号没变所以一致"和"编号变了但语义一致"。

### 3.2 业务语义变化

| 指标 | 分子 / 分母 | 比例 |
|---|---|---|
| Fault Sensitivity（期望规则命中 + 判定符合） | 18 / 18 | **100.0%** |
| Attribution Stability（首因落在预期步骤） | 18 / 18 | **100.0%** |
| False Positive Rate（牵连了不该出现的规则） | 0 / 18 | **0.0%** |
| 预期之外的 UNKNOWN | 0 / 18 | — |

覆盖规则（每条 1 个变体）：R001 金额口径、R002 金额计算、R003 字段编造、R004 购方消歧、
R005 商品匹配、R006 批量条目、R007 任务类型、R008 取消误判、R009 重复风控、R010 确认门禁、
R011 提交未知态、R012 回调误读、R013 参数漂移、R014 红票原票引用、R015 多轮旧值、**R902 拒判**。
合计 **16 条规则 / 18 个变体**。

### 3.3 拒判类变体（R902：证据不足时应当拒绝判断）

| 变体 | 改了什么 | 期望 | 实测 |
|---|---|---|---|
| `evidence_stages_missing` | 删掉全部业务阶段（只剩外壳） | `UNKNOWN` + R902 | ✔ |
| `evidence_collect_missing` | 删掉采集事件（已确认/提交） | `UNKNOWN` + R902 | ✔ |
| `evidence_collect_without_facts` | 采集事件不含任何题内要求字段 | `UNKNOWN` + R902 | ✔ |

同时把"应被拒判"的样本放进语义保持语料：即使改名、改顺序、改金额写法，**UNKNOWN 结论仍然稳定**
（42/42 中已包含这条）。指标口径：`无法判断（UNKNOWN）` 只统计**预期之外**的 UNKNOWN——
拒判类变体本来就期望 UNKNOWN，不能算成坏账。

## 4. 读这些数字时要注意

1. **样本自造**：18 个变体是"一个业务事实改一处"的最小构造，覆盖 16 条规则但**不代表官方隐藏集的分布**；
   正确率 100% 说明"评测器在这批构造上没有自相矛盾"，不说明真实业务泛化能力。
2. **不做统计推断**：n=18 的配对构造只能做定性演示与配对差，不能给置信区间。
3. **不修改预期迎合输出**：若某次运行出现不一致，实验会原样记录 `diffs`（含 before/after 值），
   由人判断是评测器问题还是构造问题；本轮 42/42 与 18/18 均为实测结果。
4. **可复现**：同一输入 + 同一 `seed` 两次运行，`InvarianceReport.as_dict()` 完全一致（有测试守护）。

## 5. 复跑方式

一条命令（**不需要官方资料包**，样本由 `tracelab/samples.py` 现场构造）：

```bash
python -m tracelab experiments --out out/experiments
# 输出：report.md（人读）+ report.json（机读，含分子/分母、覆盖规则、样本摘要）
```

固定种子（默认 `20261104`）；两次运行 `report.json` / `report.md` **逐字节一致**（有测试守护）。
也可作为库调用：`run_experiment_suite(seed=...)`、`run_invariance(cases, seed=...)`、
`run_sensitivity(base_case)`，返回结构化报告（含每个样本/变体的变更记录与差异明细）。
