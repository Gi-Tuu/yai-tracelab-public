# 评测器版本对照（同批数据，非模型对比）

## 目的

回应初赛反馈中的“评测集/评测器本身改进证明不足”：在**同一批 Case、同一批人工参考**上比较旧版本与当前版本，避免把模型换版、数据扩充或报告变长当成评测改进。

## 对照口径

| 项 | 旧版 | 当前 |
|---|---|---|
| 旧版基准 | `311cc6a`（0.3.0 审计后版本） | 当前 `main` |
| 数据 | 初赛公开训练集 14 Case / 28 run | 同左 |
| 人工参考 | 官方公开训练参考标注 | 同左 |
| 模型/Prompt | 不调用模型，初始确定性评测器 | 同左 |
| 命令 | `python -m tracelab evaluate --cases ... --labels ... --out ...` | 同左 |

> 该对照只比较**初始评测器**。复赛 final-round Judge 是新子系统，不能与初赛评测器混算成一个分数。

## 训练集结果

| 指标 | 旧版 | 当前 |
|---|---:|---:|
| 任务处理正确率 | 100.0% | 100.0% |
| 实际出票状态准确率 | 100.0% | 100.0% |
| 版本方向准确率 | 100.0% | 100.0% |
| 首错事件 EM | 100.0% | 100.0% |
| 根因标签 macro-F1 | 100.0% | 100.0% |
| 证据 ID 有效率 | 100.0% | 100.0% |

训练集是规则归纳数据，不能用于宣称泛化；这里只能确认**没有回归**。

## Holdout 结果

同一批 8 Case / 16 run，第二标注者盲标：

| 指标 | 旧版 | 当前 |
|---|---:|---:|
| 任务判定一致率 | 87.5% | 87.5% |
| 开票状态一致率 | 100.0% | 100.0% |
| 证据 ID 有效率 | 100.0% | 100.0% |
| 标签精确匹配率 | 56.25% | 56.25% |

结论：**当前版本没有通过提高初始评测器分数来制造“改进”；在这批 holdout 上是持平、无回归。**

## 真正能证明方法价值的对照

同批 holdout 上的消融（不改变数据与人工参考，只改变评测方法）：

| 方法版本 | 任务正确率 |
|---|---:|
| full（规则 + 证据复核） | **87.5%** |
| terminal_only（只看终态） | 62.5% |
| generic_health（通用健康检查） | 68.8% |
| business_only（仅业务规则） | 80.0% |

这组数字说明：在相同 Case 上，去掉过程证据/领域语义会明显退化；但不能反过来声称“当前初始评测器比旧版更准”。

## 当前仍缺的“版本改进”证据

要严格证明“旧 Judge → 新 Judge 有改进”，需要：

1. 保留一个旧 Judge/Prompt 版本；
2. 在同一批数据、同一人工参考、同一模型参数上各跑一次；
3. 输出改善、无变化、退化三类结果；
4. 不把根据测试结果再调优的批次当独立验证。

当前 Judge Prompt 已冻结，仓库里没有可比的旧 final-round Judge 版本，因此**不伪造“旧版更低、新版更高”的数字**。现有可交付的版本对照是：

- 初始评测器旧/新：持平、无回归；
- 同批 holdout 消融：full 优于 terminal/generic/business_only；
- 官方 max 与自有模型对照：96.5% vs 88.0%（模型敏感性，不是评测器改进）。

## 复现

```powershell
# 旧版 worktree
git worktree add --detach E:\Competition\tracelab-old 311cc6a

# 训练集
python -m tracelab evaluate `
  --cases  <公开训练轨迹.jsonl> `
  --labels <公开训练参考标注.jsonl> `
  --out    <旧版输出>

# 当前版本
python -m tracelab evaluate `
  --cases  <公开训练轨迹.jsonl> `
  --labels <公开训练参考标注.jsonl> `
  --out    <当前输出>
```

Holdout 对照需先把 `docs/holdout/labels.jsonl` 转换为官方标签格式；该转换只用于复现，不改原始标注。

## 结论边界

- 不能把训练集 100% 当成泛化；
- 不能把模型对比当成评测器版本改进；
- 可以说“初始评测器同批无回归”，不能说“初始评测器准确率提升”；
- 复赛真正的增量是双业务接入、专属 Judge、四态/证据、收据链、专项抗干扰和交付检查，而不是初始分数。
